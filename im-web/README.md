# IM 助手 · 网页端

Vue 3 + TypeScript + Vite。注册、登录、验证码、会话恢复和联系方式绑定通过
`im-user-service` 处理；好友申请和联系人接入 MySQL。单聊消息在
`im-chat-service` 中持久化，并通过 WebSocket 通知另一端刷新。讨论室支持建群、邀请好友、
消息历史和未读；在群聊中选择成员点名后，通知会保存并实时推送。群聊摘要
由本机模型生成并保存到 MySQL；个人待办也保存在 MySQL，翻译仍是本地演示。

## 本地运行

1. 在 `im-backend` 执行 `docker compose up -d`，启动 MySQL 和 Redis。
2. 在 PowerShell 中启动用户服务（使用 `.env` 里的数据库密码）：

   ```powershell
   cd D:\im-assistant\im-backend
   $env:IM_MYSQL_PASSWORD = Read-Host "输入 .env 中的 IM_MYSQL_PASSWORD"
   .\mvnw.cmd -pl im-user-service spring-boot:run "-Dspring-boot.run.profiles=dev"
   ```

3. 打开另一个 PowerShell 窗口启动聊天服务（8082）：

   ```powershell
   cd D:\im-assistant\im-backend
   $env:IM_MYSQL_PASSWORD = Read-Host "输入 .env 中的 IM_MYSQL_PASSWORD"
   .\mvnw.cmd -pl im-chat-service spring-boot:run
   ```

4. 打开第三个 PowerShell 窗口启动前端：

   ```powershell
   cd D:\im-assistant\im-web
   npm ci
   npm run dev
   ```

打开 `http://localhost:5173/`。Vite 将 `/api/chats`（含 WebSocket）转发到 8082，其他 `/api` 请求转发到 8081。
`npm run build` 检查类型和构建；`npm test` 检查认证和好友接口的数据契约。

## 体验路径

1. 创建账号：填昵称、唯一账号、密码以及手机号或邮箱；服务端先检查格式，
   通过后进入验证码页。两种联系方式都填时，分别获取并填写两条验证码；
   提交时服务端消费验证码并检查唯一性，验证通过才会写入 MySQL。
2. 用已注册的手机号或邮箱，通过密码或验证码登录。刷新页面时，前端使用
   `GET /api/auth/me` 检查当前会话；退出时调用服务端注销接口。
3. 在设置中使用当前密码和验证码补绑另一种联系方式。
4. 在另一个浏览器或标签页注册第二个账号（每个标签页有独立登录会话），
   用已绑定的手机号或唯一账号直接发送好友申请（页面不会透露该账号是否存在）；第二个账号在“好友申请”中同意，然后双方
   刷新联系人列表即可看到真实好友。申请可拒绝或撤回，好友可移除。
5. 点击好友列表中的“发消息”，双方可实时看到单聊消息和未读角标。断线后自动重连，
   从当前会话最后应用的消息 ID 逐页补拉（每页 50 条）；群聊同样补拉。
   可将接收方标签页临时切到浏览器开发者工具的 Offline 模式，另一端发送
   超过 50 条，再恢复在线，检查当前会话的消息连续且不重复。
   重新加载页面或退出后再次登录，同一浏览器会按账号和会话保存的游标补拉；
   首次访问该会话则从最新 50 条开始，旧消息可继续向前翻页。
6. 在消息页创建讨论室、邀请好友，双方进入同一个讨论室发送消息。新成员只看到加入后的消息；
   切换会话可检查未读角标，群主可继续邀请好友（每次最多 20 人，总人数最多 50 人）。
7. 在群聊输入框点“@”选择另一位成员后发送消息；被点名者的通知页会出现提醒，
   点击可跳到原消息。退出再登录，未读通知仍在；同一消息编号重试不会重复提醒。
8. 若已安装本机 Ollama，先下载本地模型（例如 `ollama pull qwen3:4b`），并在启动
   聊天服务的 PowerShell 窗口设置 `$env:IM_SUMMARY_MODEL = "qwen3:4b"`。
   群聊右侧助手可生成和查看摘要。非群成员会被拒绝；后来加入者看不到
   依据其加入前消息生成的摘要。未配置本地模型时页面会明确显示错误。
9. 在“我的待办”创建、完成或删除个人待办，刷新或换浏览器登录仍可查看；
   待办只属于创建它的账号，不会显示给讨论室中的其他成员。每页最多加载 50 项。
   旧版浏览器演示待办不会自动导入服务端，需要重新创建真实待办。
10. 打开私聊或讨论室，点击顶部放大镜，输入至少 2 个字符搜索当前会话的服务端历史消息；
    结果按时间倒序，每页最多 20 条，可加载更早结果。左侧搜索框仅用于筛选会话名称。
    讨论室新成员搜不到入群前的消息；搜索结果只在当前页面展示，切换会话即清空。
    点击结果的“查看上下文”会显示该消息前后最多各 20 条，可继续向两侧翻页；
    返回最新消息后继续收发。上下文独立于实时消息列表，不会改写离线补拉游标。

开发模式的验证码由**后端返回并显示在页面**，没有发送短信或邮件；只能用于
本机联调。此前浏览器中创建的演示账号没有写入 MySQL，需要重新注册测试账号。
注册后如需重新测试，请换一个未使用的唯一账号和联系方式。

服务端不可用时页面会显示错误，不会回退到浏览器演示账号。用户服务已启动且
`/actuator/health` 正常后再试；如果 8081 端口被其他 Java 进程占用，请先处理
端口冲突。登录 token 仅保存在当前标签页的 `sessionStorage`；偏好演示数据按
服务端用户 ID 保存在 `localStorage`，刷新后可恢复。各账号、会话的消息同步游标
保存在浏览器的 `sessionStorage` 和 `localStorage`（只有 ID，没有消息正文）；
群聊、私聊和点名通知仍以 MySQL 为准。浏览器存储被清除或换一台设备时，从
最新消息页开始，较早的消息仍可分页查看。

浏览器支持本机 Web Speech 识别、中文本机语音包且授予麦克风权限时，可转写本人的麦克风语音。
如需下载中文语音包，界面会先征求确认；不支持本机识别时请使用文字输入，不会自动改用云端识别。
识别结果只显示在当前对话的本地预览，不会自动发送；点击“填入输入框”、检查和编辑后再点击“发送”。
切换对话、页面、账号或隐藏标签页会丢弃未确认的语音预览。此功能不转写其他成员的语音。
示例译文和讨论线索仍为本地演示内容。后续继续完善语音与翻译。
